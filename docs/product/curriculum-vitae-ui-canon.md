# Curriculum VitÆ UI Canon

**Status:** Canon  
**Scope:** first-run onboarding experience, visual presentation, motion language, layout hierarchy, approved asset usage, and transition into the Office Desk.

## 1. Purpose

Curriculum VitÆ is the first-run onboarding experience for Goblin Black Office.

It is not a generic signup wizard.

It is a **command briefing** delivered inside the Black Office environment, led by **Cmdr. Æterna Skyeward**, and designed to collect enough intelligence that the Office can begin operating effectively without repeatedly interrogating the user later.

The onboarding must feel:
- militaristic
- premium
- near-future
- spatial
- cinematic in moderation
- efficient once it begins
- unmistakably part of the Black Office

## 2. Narrative sequence

First-run sequence:

1. startup charge completes
2. breach reveals graphite access door
3. white center seam ignites
4. split-center door opens
5. white flash transition
6. Æterna is revealed waiting beyond the threshold
7. she delivers the opening line
8. Curriculum VitÆ begins
9. briefing completes
10. interface retracts into the Office Desk
11. Æterna collapses into her persistent advice-box state

### Opening line

Canonical opening line:

> “It’s about time you got here, Commander. The troops are getting restless. Let’s get you into Intel for a quick briefing. Right this way, sir.”

This line may be refined slightly for cadence, but the meaning and tone are canonical.

## 3. Core visual concept

Curriculum VitÆ is a **holographic command interface projected over the Black Office environment**.

This supersedes any earlier paper-dossier-first onboarding direction. Paper may exist as environmental set dressing, but it is not the primary interaction metaphor.

This means:
- the user remains visually inside the Black Office at all times
- onboarding is not presented on a blank background or generic form page
- the command desk / office environment remains visible beneath and behind the projected UI
- the UI feels layered, translucent, and spatial rather than flat and opaque

### Design intent

The effect should feel like:
- a command layer coming online
- Æterna temporarily assuming full-screen briefing authority
- projected intelligence overlays assembling over a real operational environment

Not:
- a SaaS form
- a webpage modal
- a cyberpunk toy overlay
- a sci-fi game HUD parody

## 4. Environment

### 4.1 Base layer

The base visual layer is the **default Black Office environment**.

This may be:
- the command desk
- a generalized Office interior
- a black/graphite branded environment derived from the app’s default home setting

The environment should remain:
- dark
- spatial
- textured
- visibly physical

It should not be visually busy enough to compete with the holographic interface.

### 4.2 Holographic layer

All onboarding controls and content live in a projected holographic layer above the base environment.

This layer uses:
- translucent cyan / cobalt panes
- projected lines and frames
- mild scan / projection behavior
- layered depth
- subtle edge glow
- restrained motion

## 5. Approved assets

The onboarding UI must use the approved canon assets.

### Required canon assets

- approved **Æterna straight-on headshot**
- approved **Æterna command portrait** where needed
- approved **app badge / insignia**
- approved **startup splash / access door sequence assets**
- approved **Black Office palette system**

### Rule

No substitute generated images are to be used in production onboarding unless explicitly approved as canon.

## 6. Layout system

The canonical onboarding layout has four primary zones:

1. **Background environment layer**
2. **Left progression rail**
3. **Central working pane**
4. **Æterna portrait / command presence layer**

### 6.1 Left progression rail

The progression rail remains visible throughout onboarding.

Purpose:
- orient the user
- reinforce mission/briefing structure
- reduce ambiguity about scope and progress

Suggested section sequence:
1. Commander
2. Organization
3. Structure
4. Finance & Tax
5. Operations
6. Deployment

Behavior:
- current section is highlighted
- completed sections receive a completion trace
- future sections remain visible but subdued

### 6.2 Central working pane

The central pane contains the active step content.

Characteristics:
- translucent holographic panel
- layered over the Office environment
- primary form and explanation area
- structured, clean, and not overly text-heavy

The pane should feel like a command file / intelligence console rather than a basic card.

### 6.3 Æterna presence layer

Æterna remains visible throughout the onboarding experience.

She should appear:
- above the content plane
- slightly behind or floating adjacent to the active content
- clearly part of the interface hierarchy
- visually distinct from the field/input region

She is not a static decorative portrait. She is the command presence.

Æterna remains visually corporeal first. Holographic treatment belongs to her command UI, HUD, framing, and projection effects rather than making her body read as a transparent hologram.

### 6.4 Status instruments

The onboarding should include:
- **Intel completeness indicator**
- section progress visibility
- current step title
- current briefing context

These should read as instruments, not gamified badges.

## 7. Æterna presentation

### 7.1 Visual treatment

Use the approved straight-on headshot as the persistent onboarding presence.

Presentation rules:
- floats above the content plane
- softly framed in cobalt/cyan command styling
- lightly animated
- integrated with a holographic support layer
- never mistaken for goblin UI

### 7.2 Idle animation

Æterna’s onboarding portrait may include subtle idle behavior:
- blinking
- very slight breathing motion
- tiny head/gaze adjustment
- faint HUD shimmer
- restrained edge glow fluctuation

This should be minimal.

She should feel present, not busy.

### 7.3 Speaking behavior

When Æterna is “speaking” or when her line updates:
- subtle cyan pulse
- tiny waveform or activity trace
- mild emphasis on the portrait frame
- optionally a slight eye/facial shift

Avoid:
- exaggerated mouth-flap animation
- bobbing
- mascot-like chatter behavior

### 7.4 Hierarchy rule

Æterna remains visually above the informational layer.

She is:
- not a sidebar widget in onboarding
- not a small corner helper
- not equivalent to a decorative assistant bubble

Curriculum VitÆ is her briefing space.

## 8. Palette and material logic

### 8.1 Command palette

The onboarding holographic interface uses Æterna’s palette:
- cobalt
- electric blue
- cyan
- pale projected blue
- deep blue-black transparency

### 8.2 Office/environment palette

The underlying Black Office environment uses:
- graphite
- blackened steel
- slate
- restrained green-steel accents
- physical surfaces and hardware

### 8.3 Interaction between palettes

The onboarding works because the palettes are layered, not merged.

Rules:
- holographic UI = command palette
- background environment = Black Office palette
- goblin greens remain secondary in onboarding
- command colors should dominate the briefing UI

## 9. Motion canon

Motion is part of the onboarding canon.

The interface must not simply hard-cut from one static form to another.

### 9.1 Screen-to-screen transitions

When progressing between onboarding sections:
- current pane compresses or sweeps aside
- outgoing elements collapse into lines/data traces
- incoming pane assembles from wireframe to solid holographic form
- transition is crisp and controlled

The motion should feel like **reconfiguration**, not page navigation.

### 9.2 Backward transitions

Backward movement should use the same motion language in reverse.

It should not feel like a different system.

### 9.3 Section completion

When a section is completed:
- the corresponding progression-rail item receives a clean completion trace
- the Intel completeness indicator advances smoothly
- the next pane assembles into place

### 9.4 Conditional-field reveal

Conditional fields should not pop into existence abruptly.

Instead:
- child fields unfold from the parent control
- use a short scan-line or projected expansion effect
- preserve spatial continuity

### 9.5 Æterna motion

Æterna motion remains restrained and separate from pane transitions.

She may:
- pulse lightly when speaking
- shift subtly as new panes arrive
- maintain a stable visual anchor while the content reconfigures

### 9.6 Final onboarding exit

At the end of the briefing:
- the onboarding holographic layer retracts into the command desk
- the environment beneath becomes the active Office Desk
- Æterna shrinks smoothly into her persistent advice-box state

This transition is important and should feel ceremonial but efficient.

## 10. Screen structure

The onboarding should be divided into short, structured sections.

### Canonical section sequence

1. **Commander identity**
   - full name
   - preferred name
   - email
   - password
   - optional later contact preferences

2. **Organization profile**
   - legal business name
   - operating/trade name
   - business type
   - legal structure
   - physical / online / hybrid
   - address or service-area jurisdiction
   - primary currency

3. **Structure & relationships**
   - parent company
   - subsidiaries/divisions
   - franchise status
   - related business structure
   - shown conditionally when relevant

4. **Finance & tax**
   - reporting currency
   - fiscal year-end
   - tax registration status
   - GST/HST number if applicable
   - provincial/state tax registrations as relevant
   - tax handling defaults if known

5. **Operational defaults**
   - typical services/work
   - use of employees/subcontractors
   - payment terms
   - accounting platform optional
   - default practices useful to specialists

6. **Deployment**
   - briefing complete
   - first suggested actions
   - Office Desk entry

### Content-density rule

Each section should feel:
- complete
- useful
- not overloaded

Users should not face a giant wall of tiny fields.

Break long capture flows into visually stable sections.

## 11. Input design

Inputs should match the command-briefing aesthetic.

Rules:
- fields should feel integrated into the holographic system
- large enough for mobile use
- clear labels
- obvious active/focus state
- strong contrast without looking noisy

### Recommended behaviors

- focused fields gain a brighter projected edge
- selected chips/toggles illuminate clearly
- conditional branches animate open beneath parent controls
- helper text remains secondary and concise

Avoid:
- giant glowing neon inputs
- indistinct borders
- overly decorative field chrome
- unreadable low-contrast text

## 12. Mobile behavior

The onboarding must adapt gracefully to mobile.

### Mobile rules

- preserve the Black Office environment
- preserve the holographic command feel
- preserve the progression system
- reduce clutter
- avoid tiny sidebars

### Mobile adaptation

- progression rail may collapse into top step pills or compact indexed tabs
- Æterna portrait may reduce in scale but should remain visible
- active working pane becomes vertically stacked
- Intel completeness remains visible but compact
- primary action remains thumb-reachable

The mobile version must still feel like the same system, not a simplified fallback app.

## 13. Sound and ambience guidance

If motion/audio are used later:
- subtle UI tones
- faint command-room ambience
- light holographic assembly tones
- restrained section-advance confirmation
- no cartoon bleeps
- no aggressive sci-fi noise

Audio is optional for product implementation, but the UI should support it conceptually.

## 14. Deployment screen

The final onboarding state should feel like a **handoff into live command**.

Requirements:
- onboarding layer remains visible for one final moment
- Office Desk beneath is revealed as active destination
- suggested first actions are shown
- Æterna delivers a concise final line

Suggested closing tone:

> “That’ll do, Commander. Intel has enough to work. I’ll stay on comms.”

Then:
- full-screen briefing presence retracts
- persistent advice box remains

## 15. Canon rules

The following are mandatory for Curriculum VitÆ:

- onboarding happens inside the Black Office
- holographic interface overlays a physical command environment
- approved Æterna headshot is used as the persistent anchor
- Æterna remains visible throughout the process
- command palette remains visually separate from goblin/physical palette
- left progression rail or equivalent progression system remains visible
- screen-to-screen transitions are animated as interface reconfiguration
- final onboarding exits into the Office Desk
- Æterna collapses into persistent advice-box mode at the end

## 16. Explicit anti-patterns

Do not drift into:
- generic form-wizard onboarding
- flat SaaS cards on blank backgrounds
- opaque white/gray forms
- static dead portrait art
- fantasy-elf presentation
- goblin-green-dominant command UI
- abrupt page swaps with no motion logic
- overly gamified progress treatment
- “chatbot onboarding” with no command structure
- animation for its own sake

## 17. Implementation note

This document defines the **visual and interaction canon** for Curriculum VitÆ.

Any new art, screens, motion treatments, or UI elements introduced during implementation that materially change this direction require **explicit canon approval before commit**, per the current project rule.

## 18. Canon summary

> **Curriculum VitÆ is a holographic command-briefing interface projected over the Black Office environment, led by a lightly animated persistent Æterna portrait, using layered cyan/cobalt UI panes, a mission-style progression rail, and screen-to-screen reconfiguration animations instead of static form changes.**
